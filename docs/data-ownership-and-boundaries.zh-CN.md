# 数据所有权与边界

Everthread 不要求用户删除或匿名化自己的伴侣聊天原文。

对长期 AI 伴侣来说，原始聊天往往就是关系温度的来源。问题不在于“原文是否私密”，而在于“原文放在哪里、什么时候召回、召回多少、由谁拥有”。

## 用户自己的部署

用户可以保留：

- 完整聊天原文
- 日记
- 附件
- 向量
- 摘要
- 角色和偏好配置

这些数据应该属于用户，而不是某个单一 App。

## 公开仓库

公开仓库应该只放：

- 虚构示例
- schema
- 模板
- 架构文档
- 流程说明

公开仓库不应该放：

- 真实聊天原文
- 真实 API key
- 真实服务器地址
- 真实账号截图
- 能反推出个人身份的路径或文件名

## 原文策略

Everthread 推荐：

- 原文保存在 Cold Warehouse。
- Hot Brain 只保存被接受的长期记忆。
- Dream Layer 把原文整理成日记或 digest。
- Recall Gate 控制每次召回预算。
- 用户明确要求时，可以回看原文。

## 权威顺序

当记忆冲突时，建议权威顺序：

1. 用户当前明确表达
2. 当前项目状态
3. accepted memory
4. Dream 日记
5. 月度 digest
6. 原始聊天
7. 模型推断

原始聊天很重要，但它可能过时。当前明确表达永远优先。
