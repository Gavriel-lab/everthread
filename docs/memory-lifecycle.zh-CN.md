# 记忆生命周期

Everthread 把记忆从“刚发生”到“长期沉淀”分成几个状态。

## 1. Capture 捕获

捕获是把聊天、事件、文件、用户明确要求保存的内容放入候选区。

捕获内容应该记录：

- 来源
- 时间
- 简短摘要
- 是否包含原文
- 初步标签
- 建议脑区

## 2. Candidate 候选

候选记忆不是长期记忆。它只是“可能值得保存”。

候选需要经过评分：

- 情绪显著性
- 复现频率
- 连接密度
- 用户明确程度
- 长期实用性
- 隐私或安全边界

## 3. Accepted 接受

Accepted Memory 是 Hot Brain 可以常驻读取的内容。

它应该满足：

- 对长期关系或任务有价值
- 表述稳定
- 不只是一次性噪声
- 可被未来端点理解
- 不会覆盖更高权威的当前状态

## 4. Dream Consolidation 梦境沉淀

Dream Layer 会定期整理候选和 accepted memory。

常见动作：

- retain：保留
- deepen：加深
- compress_to_diary：压缩进日记
- sink：沉入冷仓库
- soft_forget：降低主动召回概率

## 5. Recall 召回

召回时不要把搜索结果机械贴回聊天。

推荐流程：

1. 先判断当前问题是否需要旧记忆。
2. 先查 Hot Brain。
3. 再查 Dream 日记或月度 digest。
4. 必要时查 Cold Warehouse。
5. 把证据转成自然语言回忆。

## 6. Decay 衰减

不是所有记忆都应该永远活跃。

记忆可以衰减到：

- active：高频可召回
- warm：相关时召回
- cold：深层检索才召回
- archived：只保留原文
- soft-forgotten：默认不主动提起

软遗忘不是删除。它只是降低主动出现概率。
